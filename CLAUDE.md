# CLAUDE.md — svedsolution.com

Working reference for this repo. Read it before changing anything. The project has a
history of changes that looked fine in source and broke in production, so the rule is:
**verify against the live site, don't assume a change worked.**

---

## What this is

Marketing site for **SVED Solution** — an AI visibility & 360° SEO agency (GEO / AEO /
LLM SEO). It's a static site generated by one Python script (`build.py`), hosted on
**Cloudflare Pages**, with the audit tool, contact form, lead capture and CMS auth
running as **Pages Functions**.

Live: https://svedsolution.com · Repo: github.com/ved9871/svedsolution (private)

---

## Build & preview

```bash
pip install -r requirements.txt      # only dependency: markdown==3.7
python build.py                       # generates the site into dist/
python -m http.server 8787 --directory dist   # preview at http://localhost:8787
```

`build.py` prints every file it writes with byte sizes, then a summary line
(core pages + services + industries + posts + static, and the sitemap URL count).
Read that output — a page silently missing from it usually means a content or routing bug.

Python 3.10+ works. There is no Node build step; the `functions/` folder is compiled by
Cloudflare, not locally.

## Deploy flow

- **Every push to `main` triggers a Cloudflare Pages build.** There is no manual deploy.
- Pages build settings: build command `pip install -r requirements.txt && python build.py`,
  output directory `dist`, root directory blank, framework preset None.
- `functions/` is auto-detected and compiled into Workers — `/api/audit`, `/api/contact`,
  `/api/auth`, `/api/callback`, `/api/leads` become live endpoints. You don't configure them.
- Roll back from Cloudflare Pages → Deployments → Rollback on any prior build.

**After changing an environment variable, the build must be re-run** (Deployments → Retry).
Functions read variables at build time, not request time.

## Content model (blog posts)

A post is `content/blog/<slug>.md` with YAML front matter. Keys the build reads:

| Key | Notes |
|---|---|
| `slug` | defaults to filename; sets the URL — post publishes at `/insights/<slug>/` (NOT `/blog/`) |
| `title` | |
| `description` | meta description, 140–160 chars |
| `answer` | the 40–60 word direct answer — renders as the highlighted answer block, the passage AI is most likely to quote |
| `category` | defaults to "Insights" |
| `date` | ISO `YYYY-MM-DD` — drives ordering **and the publish gate below** |
| `author` | defaults to "Ved Prakash" |
| `readtime` | defaults to "8 min" |
| `image` | OG image filename in `assets/` |

JSON-LD (`BlogPosting` + `BreadcrumbList` + `FAQPage`) is emitted automatically from the
visible text (see `post_ld` / `post_schema`). Don't hand-write schema into post bodies.

Full editorial checklist: `marketing/BLOG-PUBLISHING-STANDARD.md`. Every post ships with
four deliverables (article + social pack + design brief + video script), packs saved under
`marketing/packs/<slug>.md`.

## Non-obvious failure modes (these have caused real bugs)

1. **The build hard-fails if a canonical points at a page that wasn't written.**
   `verify_canonicals()` raises `SystemExit` when any `<link rel="canonical">` targets a
   URL with no corresponding file in `dist/`. A canonical aimed at a 404 quietly drops the
   page from the index and nothing else would catch it — so a slug typo will stop the whole
   build. If a Pages deploy fails, check this first.

2. **Future-dated posts are hidden until a rebuild happens on/after their date.**
   The publish-date gate drops any post whose `date` is after today — not written, not in
   the sitemap, not in listings. A future date = a scheduled post, BUT Cloudflare only
   builds on push, so a scheduled post needs a rebuild to fire on its publish day (the daily
   deploy trigger). No trigger on that day = the post stays invisible. To publish now, the
   date must be today or earlier.

3. **Line endings are enforced and binaries are marked.** `.gitattributes` sets `eol=lf`
   for text and marks fonts/images/archives as `binary` so no platform's CRLF normalization
   corrupts them. Don't override this or commit CRLF text files.

4. **`dist/` is gitignored — never commit build output.** The site is built fresh on
   Cloudflare from source. Committing `dist/` causes confusing diffs and stale pages.

5. **`markdown==3.7` is pinned.** If the dependency is missing the build falls back to a
   paragraphs-and-headings-only renderer so it never crashes — meaning a broken install can
   ship degraded posts that still "build". Keep the pin; don't assume rich markdown rendered.

## Environment variables & bindings (Cloudflare Pages → Settings)

| Name | Purpose | Required |
|---|---|---|
| `PSI_KEY` | PageSpeed Insights API key — Core Web Vitals check; without it the API 429s | effectively yes |
| `RESEND_KEY` | Resend API key — contact form delivery | yes for forms |
| `TO_EMAIL` | inbox the contact form delivers to | yes |
| `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET` | GitHub OAuth for the `/admin/` CMS | CMS only |
| `AUDIT_KV` (KV binding → namespace `SVED_AUDIT`) | audit rate limiting + 24h result cache | recommended (edge-cache fallback if absent) |

## Content rules (non-negotiable)

- **Never name clients.**
- **No GST / tax details.**
- **No promised rankings or guaranteed AI citations.**
- **Every claim carries a real number.**

Brand tokens: navy `#0B1219` / `#101A24`, electric green `#00FFB2` → `#00A5FF`,
Poppins headings, JetBrains Mono labels, tagline "Google ranks pages. AI recommends brands."
